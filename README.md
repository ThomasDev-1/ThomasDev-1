# 🚀 Selected Work

## 📺 LarpTube

**A video platform built from the ground up.**

LarpTube explores what goes into building a modern video-sharing platform — accounts, discovery, subscriptions, libraries and content delivery wrapped inside a familiar user experience.

Rather than building another portfolio demo, I wanted to tackle the engineering challenges behind a platform people already understand.

**Built around:**
`Full-Stack Development` · `Authentication` · `Content Discovery` · `Video` · `Web Architecture`

→ [Visit LarpTube](https://larptube.com/)

---

## 🎓 ScheduleX

**A better timetable experience for students.**

ScheduleX started because I was frustrated with the timetable software I had to use every day.

So I built an alternative.

It connects with **WebUntis** and turns university timetable data into a cleaner mobile experience, including lesson information, schedule changes, notifications, subject customisation and calendar views.

The project moved beyond a prototype into real-world beta testing with students.

**Built around:**
`Android` · `APIs` · `Notifications` · `Product Design` · `Real-World Testing`

---

## 🐦 Outhatched

**A multiplayer hero shooter — except everyone is a bird.**

Outhatched is one of my more ambitious engineering projects: an online game combining character abilities, aerial movement, combat and objective-based multiplayer gameplay.

Building it has meant working beyond individual gameplay scripts and thinking about networking, backend services, game architecture and how multiple systems interact in a real-time environment.

**Built around:**
`C#` · `Unity` · `Multiplayer` · `REST APIs` · `Game Systems`

→ [outhatched.com](https://outhatched.com/)

# 🧠 Engineering Philosophy

### Build things that leave localhost.

I learn fastest when I'm solving real problems.

That means I would rather build a complete product, put it in front of users and discover where it breaks than spend months building something nobody ever touches.

My approach is usually:

**Understand the problem → simplify it → build → ship → measure → iterate.**

I care about clean architecture and good engineering practices, but ultimately software exists to be **used**.
